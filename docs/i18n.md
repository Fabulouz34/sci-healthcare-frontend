# Internationalisation (i18n)

SCI Healthcare supports multiple languages across West and East African corridors:
- **English (`en`)** (default)
- **French (`fr`)** (West Africa)
- **Swahili / Kiswahili (`sw`)** (East Africa)

---

## Architecture

- **Message Catalogues:** JSON files located in `src/messages/` (`en.json`, `fr.json`, `sw.json`).
- **Configuration:** `src/i18n/config.ts` lists supported locales, display labels, date/number locales, and imports the JSON catalogues.
- **Provider & Hook:** `src/i18n/LocaleContext.tsx` provides `LocaleProvider` and the `useLocaleContext()` hook:
  - `t(key, params?)`: Translates dot-delimited message paths (e.g. `t('voucher.history')` or `t('voucher.scanToView', { id: '42' })`).
  - `locale`: Current active locale (`en`, `fr`, or `sw`).
  - `setLocale(locale)`: Persists user preference to `localStorage` (`sci-locale`) and a `NEXT_LOCALE` cookie.
- **Persistence:** the locale is a small store read through `useSyncExternalStore` — the same shape as the theme in `src/lib/theme.ts`. The server has no storage to read, so it renders English and the stored locale is applied as soon as hydration is done; server and client therefore agree and the choice never breaks hydration. The stored value is `localStorage` (`sci-locale`), falling back to the `NEXT_LOCALE` cookie when storage is blocked, then to the browser's language when we support it. `tests/e2e/language.spec.ts` pins that the choice survives a navigation, a reload and a page opened directly.
- **Formatters:**
  - `formatDate(iso, locale)` in `src/lib/amounts.ts` formats dates per locale (`en-GB`, `fr-FR`, `sw-KE`).
  - `formatUsdc(amount, locale)` in `src/lib/amounts.ts` formats currency amounts per locale.
- **Contract & Protocol Errors:**
  - `src/lib/errors.ts` provides localized dictionaries (`VOUCHER_ERRORS_I18N`, `REGISTRY_ERRORS_I18N`, `FAUCET_ERRORS_I18N`) for host contract and token errors.
  - `src/lib/disputes.ts` provides localized dispute reason descriptions.

## How to Add a New Language

To add another language (for example, Yoruba `yo` or Portuguese `pt`):

1. **Create Message Catalogue:**
   Add `src/messages/<locale>.json` modeled after `src/messages/en.json`.

2. **Register in `src/i18n/config.ts`:**
   - Import the catalogue: `import <locale> from '@/messages/<locale>.json';`
   - Add the code to `locales`: `export const locales = ['en', 'fr', 'sw', '<locale>'] as const;`
   - Add to `messages`, `localeLabels`, `localeNumberFormats`, and `localeDateFormats`.

3. **Add Error & Dispute Translations:**
   - In `src/lib/errors.ts`, add entries for `<locale>` to `VOUCHER_ERRORS_I18N`, `REGISTRY_ERRORS_I18N`, and `FAUCET_ERRORS_I18N`.
   - In `src/lib/disputes.ts`, add entries for `<locale>` to `DISPUTE_REASONS_I18N`.

4. **Verify:**
   - Run `npm run typecheck`
   - Run `npm run test:unit`

## Right-to-left layouts (#131)

The layout is direction-agnostic, so a right-to-left language needs a
catalogue, not a second set of styles.

- **Direction comes from the locale.** `src/i18n/direction.ts` maps the
  language subtag to `ltr`/`rtl` (`directionForLocale`), and
  `LocaleProvider` writes the result to `dir` on `<html>` beside `lang`.
  The server renders `dir="ltr"` because it renders English; the stored
  locale is applied after hydration, exactly like the language itself.
- **Components use logical utilities only.** `ms-`/`me-`, `ps-`/`pe-`,
  `text-start`/`text-end`, `border-s-`/`border-e-`, `start-`/`end-` resolve
  against the `dir` attribute of the document, so nothing is positioned by
  screen left or right. A physical `ml-4` in a new component is a bug: it
  will sit on the wrong side once an RTL locale ships.
- **Two exceptions live in `src/app/globals.css`.** `.mono` is
  bidi-isolated, because an address or hash is a left-to-right run even on
  an RTL page; `.rtl-flip` mirrors a glyph that encodes direction, such as
  the demo tour's arrow — apply it per icon, never to a container.
- **Testing.** `tests/e2e/rtl-layout.spec.ts` sets `dir="rtl"` by hand (the
  acceptance criterion for #131) and asserts that the header cluster, the
  table alignment and the accent stripes follow it, at desktop and 390px
  widths. Do the same when reviewing a layout change: flip the attribute in
  the devtools and check the page, since no RTL catalogue ships yet.

To add Arabic, create `src/messages/ar.json`, register `ar` in
`src/i18n/config.ts` as described above, and the direction follows — no
component has to change.
